Implemented

1. Durable tracking fields on action-card ledger
Added durable notification tracking fields:
- notificationTrackingId
- notificationLink
- notificationOpenedAt
- notificationOpenCount
- notificationLastOpenedAt
- notificationClaimStartedAt
- notificationReviewStartedAt
- notificationAuditEvents

Migration safety:
- Existing DB upgraded via PRAGMA column checks + ALTER TABLE additions.
- Defaults preserved (open count 0, tracking fields null).

2. Tracked link generation
Notification preview/send now generate and persist tracked link metadata when profile link is resolvable:
- tracked link format: /api/mealscout/intake/notifications/:trackingId/open
- trackingId is UUID-based and tied to the action card record.
- preview/send return tracking id + tracked link.

3. Open tracking endpoint
Added:
- GET /api/mealscout/intake/notifications/:trackingId/open

Behavior:
- Finds card by tracking id.
- Increments notificationOpenCount.
- Sets notificationOpenedAt on first open.
- Updates notificationLastOpenedAt on each open.
- Appends notification_opened event into notificationAuditEvents.
- Redirects (302) to canonical MealScout profile link.
- Unknown tracking id returns safe 404 text response.

Safety:
- No profile field mutation.
- No claim/ownership transfer.
- No verification changes.

4. Notification status endpoint
Added:
- GET /api/mealscout/intake/action-cards/:cardId/notification/status

Returns:
- notification state
- tracking id/link
- profile link
- open metrics (first/last/open count)
- claim/review tracking fields
- audit events
- mutationAllowed:false

5. UI and client updates
Client additions:
- previewActionCardNotification(cardId)
- sendActionCardNotification(cardId, payload)
- getActionCardNotificationStatus(cardId)

Admin UI updates (/admin/mealscout-review-queue):
- Shows tracked link + open metrics on cards.
- Adds Notification Status action.
- Adds Copy Tracked Link action when link exists.
- Keeps Preview Notification and Send/Copy Notification controls.
- Shows status in result console text.

6. Manual-send boundaries preserved
- No auto-send behavior introduced.
- manual_copy remains the default safe channel.
- email/sms still blocked unless explicit env flags are enabled.
- duplicate/conflict/replacement notifications still require explicit override.
