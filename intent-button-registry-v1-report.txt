Upload intent validation behavior
- POST /api/intake/upload-intents now requires:
  - userId
  - accountId
  - brand
  - actionId
  - actorScope
  - entityType
- Enforces:
  - brand validity
  - actorScope validity
  - actionId registered for brand+actorScope
  - entityType allowed by action
  - entityId required when action requires entity context
  - userHint required when action requires it
- Unknown/unregistered action returns:
  - error: INVALID_INTENT
- Intent snapshot now persists:
  - allowedFieldPaths
  - forbiddenFieldPaths
- Intent flags now persist and remain enforced:
  - implementationAllowed: false
  - previewRequired: true
  - approvalRequired: true

Preview/edit gate behavior
- Files can attach only to existing upload intents.
- Routing + preview never call publish execution.
- Preview endpoint returns draft-only output and stops at:
  - PREVIEW_READY or HELD_FOR_REVIEW
- No role bypasses preview/edit:
  - owner/staff/admin all remain implementationAllowed=false in this slice.

Routing conflict behavior
- Router uses action context as strong prior.
- Holds files on conflict with explicit reasons:
  - intent_evidence_conflict
  - ambiguous_or_wrong_domain
  - unrelated
  - ambiguous
- Cross-domain hints (e.g., TradeScout-like evidence under MealScout action) are held and not silently cross-routed.
- Low-confidence/ambiguous files remain held.
