# MERLIN APP BUILDER MVP SCOPE

## MVP Purpose

Merlin App Builder MVP creates the complete start-to-finish outline required to move a project from idea to product, launch, growth, and scale.

It must help builders avoid:

- Headache
- Project drift
- Missed steps
- Context loss
- Random implementation
- Premature UI work
- Unvalidated assumptions

The MVP is not a full automatic app generator.

The MVP is the operating layer that creates the correct project plan, doctrine, route, slice queue, and Codex handoff before implementation begins.

## Required MVP Output

Every Merlin App Builder project must produce:

1. Vision Outline
2. Doctrine Outline
3. Market Outline
4. Product Outline
5. Technical Outline
6. Build Slice Outline
7. Launch Outline
8. Growth Outline
9. Scale Outline
10. Project Flight Plan
11. First Codex Handoff Packet

## Vision Outline

The Vision Outline must answer:

- What are we building?
- Who is it for?
- What pain does it remove?
- Why now?
- What does success look like?

## Doctrine Outline

The Doctrine Outline must answer:

- What must always be true?
- What must never happen?
- Who has authority?
- What rules protect the product from drift?
- What rules protect users?
- What rules protect the business?

## Market Outline

The Market Outline must include:

- Target users
- Current alternatives
- Competitor gaps
- Distribution channels
- Pricing assumptions
- Early adopter wedge
- Evidence needed before scaling

## Product Outline

The Product Outline must include:

- Core user flow
- MVP features
- Non-MVP features
- User roles
- Data needed
- Admin tools
- Failure states
- Support states

## Technical Outline

The Technical Outline must include:

- Frontend surfaces
- Backend services
- Database model
- Authentication and authorization
- Storage requirements
- AI/model layer
- API contracts
- Deployment target
- Security concerns
- Monitoring requirements

## Build Slice Outline

The Build Slice Outline must break the project into executable units.

Each slice must include:

- Goal
- Files likely affected
- Acceptance criteria
- Validation commands
- Rollback risk
- Codex prompt
- Expected user-visible outcome

## Launch Outline

The Launch Outline must include:

- Private alpha
- Internal smoke tests
- First 10 users
- First 100 users
- Public launch
- Support loop
- Feedback capture
- Conversion fixes

## Growth Outline

The Growth Outline must include:

- Acquisition channels
- Referral loop
- Creator/community loop
- SEO/content loop
- Paid ads readiness
- Partnerships
- Retention mechanics
- Network effects

## Scale Outline

The Scale Outline must include:

- 1,000-user checkpoint
- 10,000-user checkpoint
- 100,000-user checkpoint
- 1,000,000-user checkpoint
- Infrastructure risks
- Support risks
- Trust and safety risks
- Revenue risks
- Hiring and operations risks

## MVP Non-Goals

The MVP must not:

- Attempt to generate a full app from one prompt
- Allow Codex execution before doctrine exists
- Allow Codex execution before a build slice is approved
- Treat user-connected models as governance authority
- Let the Council self-authorize execution
- Skip human approval at major gates
- Replace project evidence with model opinion

## First Implementation Slice

The first implementation slice must be documentation and contract coverage only.

Required docs:

- docs/merlin/MERLIN_APP_BUILDER_PLAN.md
- docs/merlin/MERLIN_APP_BUILDER_MVP_SCOPE.md
- docs/merlin/MERLIN_APP_BUILDER_CODEX_HANDOFF_CONTRACT.md
- docs/merlin/MERLIN_PROJECT_FLIGHT_PLAN_DOCTRINE.md

Required contract assertions:

- Merlin App Builder is part of Merlin.
- It is not a generic prompt-to-app generator.
- It guides projects from idea to product, launch, growth, and scale.
- Users may plug in their own AI models.
- Albion Council is the governance layer.
- Human authority is final.
- Codex is execution only.
- Doctrine must exist before implementation.
- Build slices must be approved before Codex execution.
- Every project must generate a Project Flight Plan.
