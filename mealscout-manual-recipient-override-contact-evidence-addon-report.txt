Part A: Manual Recipient Override
- Added durable fields on stored action cards:
  - manualNotificationRecipient
  - manualNotificationRecipientType
  - manualNotificationRecipientSource
  - manualNotificationRecipientReason
  - manualNotificationRecipientBy
  - manualNotificationRecipientAt
- Added endpoint:
  - PATCH /api/mealscout/intake/action-cards/:cardId/notification/recipient
- Behavior implemented:
  - Admin/operator/staff gate enforced.
  - Requires applied card or existing profile/notification link context.
  - Validates required reason and recipient format (email/phone when applicable).
  - Stores audit metadata only.
  - Notification preview can use manual recipient when extracted recipient is missing.
  - mutationAllowed:false.

Part B: Contact Evidence Add-On
- Added durable fields on stored action cards:
  - addedContactEvidenceFileIds
  - addedContactEvidenceFileNames
  - addedContactEvidenceAt
  - addedContactEvidenceBy
  - addedContactEvidenceReason
  - contactReprocessResult
- Added endpoint:
  - POST /api/mealscout/intake/action-cards/:cardId/contact-evidence
- Behavior implemented:
  - Admin/operator/staff gate enforced.
  - Validates sourceFileIds presence and validates file IDs in active intake scope.
  - Extracts contact candidates from provided files and hydrates target card contact fields.
  - Reprocesses contact context for target card path only; does not regenerate unrelated cards.
  - Returns recipient readiness summary.
  - Does not send notifications.
  - Does not apply profile mutation.
  - mutationAllowed:false.

Notification/Preview Behavior
- Preview now surfaces:
  - recipientCandidates
  - recipientAmbiguous
- Manual recipient is used for preview eligibility when extraction had recipient_missing.
- Conflicting contacts remain blocked as recipient_ambiguous.
