Implemented behavior
1) Decision state model added
- Cards now persist decision metadata:
  - decisionState: pending | approved_for_apply | rejected | deferred
  - decisionBy
  - decisionAt
  - decisionReason
- Default state is pending.
- Rejected/deferred preserve sourceFileIds and extractedFields.

2) Backend decision endpoint added
- PATCH /api/mealscout/intake/action-cards/:cardId/decision
- Accepts:
  - decisionState: approved_for_apply | rejected | deferred
  - decisionReason optional
- Returns:
  - cardId, batchId, decisionState, decisionBy, decisionAt, decisionReason, mutationAllowed:false
- Invalid decision state -> 400 invalid_decision_state
- Unknown card -> 404 action_card_not_found
- Role-gated (admin/operator/staff style gate)

3) Review queue endpoints available
- GET /api/mealscout/intake/action-cards
- GET /api/mealscout/intake/batches/:batchId/action-cards
- Cards include decision state data and remain non-mutating.

4) Dry-run behavior preserved
- POST /api/mealscout/intake/action-cards/:cardId/dry-run still non-mutating.
- Remains available irrespective of decision state.
- mutationAllowed remains false.

5) Admin Review UI section added
- Existing /admin/mealscout-review-queue now includes “Merlin Intake Action Card Review”.
- UI shows:
  - card type, entity type, confidence, title
  - extracted fields, missing fields
  - existing entity match
  - source file IDs
  - decision state + reason
- UI filters:
  - batchId, card type, decision state, confidence band
- UI controls:
  - Dry Run
  - Approve for Apply
  - Reject
  - Defer
- Controls call backend endpoints through client methods.
- Approve for Apply is clearly state-only; no publish/apply mutation added.

6) Client API additions
- getActionCards(filters)
- getBatchActionCards(batchId)
- dryRunActionCard(cardId)
- setActionCardDecision(cardId, payload)

7) Safety guarantees maintained
- No live profile mutation path added.
- No publish endpoint calls from new decision logic.
- No notifications.
- No Drive cleanup/delete behavior.
- Existing preview/dry-run behavior remains backward compatible.
